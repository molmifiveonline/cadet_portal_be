# cadet_portal_be
Cadet Portal BE

Set the backend `FRONTEND_URL` to the public portal URL, for example `https://cadet.molminavis.com`. If it contains a comma-separated list, put the public portal URL first; additional URLs are allowed CORS origins. Institute email links use this first URL with `/institute-login` and redirect to `/drives` after login. Set `INSTITUTE_LOGIN_URL` only when a separate institute login URL is required. Restart the backend after changing these environment settings.

Password reset links use a random single-use token, expire after 15 minutes, and are replaced by the next reset request. The database stores only the SHA-256 token hash. Requests are limited to five reset emails per account in any rolling four-hour window, with a one-minute resend cooldown. The sixth request returns HTTP 429 with a `Retry-After` header and the message "Your maximum limit has been reached. Please try again after some time." The database persists reservations in `password_reset_requests`; transactions serialize requests per account across backend instances. Failed email deliveries release their reservation, and cooldown-suppressed requests do not count. Password changes clear pending reset tokens without clearing the four-hour allowance, including changes made through user management. Legacy links containing only a user ID are rejected. Deploy the backend and frontend together; `ensurePasswordResetSupport` adds the three nullable reset columns, a unique token-hash index, and the request history table automatically on startup or the first reset operation. Configure SMTP or service email credentials so reset emails can be delivered; reset tokens are never logged or returned by the API.
